# Лабораторная работа № 2: процедуры, функции и триггеры

Решение всех заданий практикума «Разработка процедур, функций и триггеров в MySQL» (2026). Требуется **MySQL 8.0** и схема **Library_04** из `lab1/task1.sql`, заполненная `lab1/task2.sql`. В методичке она называется `library`; здесь сохранено имя из репозитория. Таблицы и поля используются без переименования.

## Файлы

| Файл | Задание |
|---|---|
| `task1.sql` | Функция срока чтения; `books_statistics`; шесть триггеров статистики |
| `task2.sql` | 3.1–3.5: статистика по авторам, архив, восстановление читателя, последний визит, кэш средних |
| `task3.sql` | 1–8: запреты по датам, числу книг, статусу, именам и году издания |
| `task3_corrections.sql` | 9–12: добавление точки, исправление дат, очистка названия книги |
| `task4.sql` | Пять хранимых функций контроля и актуализации данных |
| `run.sql` | Установка всех основных объектов в строгом режиме |
| `reset_corrections.sql` | Отключение четырёх триггеров коррекции перед строгим режимом |
| `tests.sql` | Проверки результатов, ожидаемых ошибок, вывод статистики до/после |

## Запуск

Команды выполняются из **корня репозитория**. Если первая лабораторная уже загружена, повторно её выполнять не нужно: `lab1/task1.sql` удаляет базу вместе с данными.

```bash
docker compose up -d
# Только для новой учебной базы:
docker compose exec -T mysql mysql -uroot -proot --default-character-set=utf8mb4 < lab1/task1.sql
docker compose exec -T mysql mysql -uroot -proot --default-character-set=utf8mb4 Library_04 < lab1/task2.sql
```

В стандартном MySQL 8 с включённым бинарным журналом честно объявленные `NOT DETERMINISTIC` функции требуют настройки доверия создателям функций. Для локального учебного сервера под root:

```bash
docker compose exec -T mysql mysql -uroot -proot -e 'SET GLOBAL log_bin_trust_function_creators=1;'
```

`SOURCE` открывает файлы в файловой системе **клиента mysql**. Для запуска клиента внутри контейнера скопируйте туда папку:

```bash
docker cp lab2 mysql-lab:/tmp/lab2
docker compose exec -T -w /tmp mysql mysql -uroot -proot --default-character-set=utf8mb4 < lab2/run.sql
```

При установленном на компьютере клиенте:

```bash
mysql -h 127.0.0.1 -P 3306 -uroot -proot --default-character-set=utf8mb4 < lab2/run.sql
```

В Workbench можно выполнить файлы `reset_corrections.sql`, `task1.sql`, `task2.sql`, `task3.sql`, `task4.sql` последовательно. Установка повторяема: пересоздаёт объекты и актуализирует кэш, сохраняя исходные книги, читателей, выдачи и архив. Старые даты в данных первой лабораторной не переписываются; проверки работают при новых INSERT/UPDATE.

## Строгие проверки и коррекция

В заданиях есть противоречие: пункт 1 запрещает возврат в прошлом, а пункт 10 требует его исправить. Поэтому предусмотрены два режима:

- После `run.sql` действует строгий режим пунктов 1–8.
- Для пунктов 9–12 выполните `task3_corrections.sql`. Он отключает два строгих триггера дат. Остальные запреты сохраняются. Коррекция выдачи выполняется перед коррекцией возврата, затем проверяются воскресенье и минимальный срок; точка добавляется перед проверкой имени (`FOLLOWS`).
- Возврат в строгий режим: сначала `reset_corrections.sql`, затем `task3.sql`.

Коррекции относятся к INSERT. Запрет смены статуса N → Y относится к UPDATE. Пример такого перехода из задания 1 проверяется **до** установки запрета из задания 3.

## Принятые правила расчёта

- `total` — сумма экземпляров `b_quantity`, `given` — число активных выдач Y, `rest = total - given`.
- Статистика автора считает все выдачи Y и N; у соавторов каждая выдача засчитывается каждому. Учитывается смена книги в выдаче и изменение связи книга–автор.
- Каскадные DELETE в MySQL не вызывают триггеры дочерних таблиц. Перед удалением читателя/книги счётчики корректируются явно; после удаления обновляются средние и необходимые даты визита.
- `last_visit` — максимум `sb_start`, либо NULL, если выдач нет. Обновляется и при смене читателя, и при изменении даты выдачи.
- `averages` хранит среднее число активных и возвращённых выдач **по всем читателям**, включая тех, у кого нет выдач. Средний срок чтения считается по возвращённым книгам. Для пустых выборок — 0.
- `restore_subscriber(id)` атомарно восстанавливает все поля записи и удаляет её из архива. История выдач, удалённая исходными каскадными FK, не восстанавливается. Процедуру вызывают вне уже открытой транзакции.
- В пункте 5 «месяц» — длина ближайшего календарного месяца; просроченные выдачи дают нулевой остаток времени. В пункте 4 «более 7» означает 8 или больше предыдущих выдач за скользящие полгода.
- `returned_books(id)` возвращает уникальные ID в порядке возрастания, через запятую; если книг нет — пустую строку. Курсор избегает ограничения длины `GROUP_CONCAT`.
- Проверка возраста издания использует год: ровно 20 лет не считается «менее 20»; ровно 100 лет разрешено пунктом 7.
- Функция дат проверяет нарушения по порядку из задания: -1, -2, -3. Код -3 логически недостижим при этом приоритете: если выдача не в будущем, возврат раньше выдачи одновременно находится в прошлом и даёт -2. В SQL оставлена отдельная ветка -3; эта неоднозначность методички явно проверяется.
- Первичные идентификаторы книг, авторов и читателей считаются неизменяемыми. Учебные проверки числа выдач рассчитаны на последовательные операции; для конкурентной промышленной выдачи нужна сериализация операций по читателю.

## Проверка

Запускайте `tests.sql` на учебной копии данных. Он временно переключает режимы триггеров, создаёт и удаляет свои фикстуры, выводит `PASS` и таблицы до/после. После успешного завершения остаётся строгий режим; автоинкрементные счётчики могут увеличиться.

```bash
docker cp lab2 mysql-lab:/tmp/lab2
docker compose exec -T -w /tmp mysql mysql -uroot -proot --default-character-set=utf8mb4 < lab2/tests.sql
```

Не используйте `--force`: неожиданная ошибка должна останавливать проверки. Ожидаемые ошибки перехватываются специальной процедурой с проверкой текста сообщения. Из-за особенностей `SOURCE` ориентируйтесь также на отсутствие `ERROR` в выводе.

Решение проверено на отдельном MySQL 8.0 с исходной схемой и данными `lab1`; сервер пользователя не изменялся.

Для исходных данных первой лабораторной на MySQL 8.0.46 получены:

| Показатель | Значение |
|---|---:|
| Всего экземпляров | 33 |
| На руках | 5 |
| В наличии | 28 |
| Среднее активных выдач на читателя | 1.2500 |
| Средний срок чтения возвращённых книг | 46.0000 дней |
| Среднее возвращённых выдач на читателя | 1.5000 |

Проверки прошли при текущей дате и при моделировании воскресенья `2026-10-18`; повторная установка сохранила 7 книг, 4 читателей и 11 исходных выдач.
