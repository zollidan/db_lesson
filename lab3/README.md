# Лабораторная работа № 3 — MongoDB

Решение всех трёх практических занятий из файла `Практикум_3_Mongodb.docx`: библиотека, **57 запросов** к ней и собственная база **«Учебный центр» с 8 коллекциями и 20 запросами**. На титульном листе документ обозначен как практикум № 5; номер папки соответствует лабораторной в репозитории.

Используются **MongoDB 8.0 и mongosh**. Для MongoDB команды записаны на JavaScript, а не SQL. Первая и вторая лабораторные, их MySQL-схема и основной `docker-compose.yml` не меняются.

## Файлы

## Запуск через Docker

Из **корня репозитория**:

```bash
docker compose -f lab3/docker-compose.yml up -d
docker compose -f lab3/docker-compose.yml exec -T mongodb mongosh --quiet --file lab3/run.js
```

При первом старте дождитесь готовности сервера:

```bash
docker compose -f lab3/docker-compose.yml exec -T mongodb mongosh --quiet --eval 'db.adminCommand({ping:1})'
```

Ожидается `ok: 1`. Скрипты доступны клиенту внутри контейнера благодаря монтированию `lab3` в `/work/lab3`. По умолчанию создаются отдельные базы `library_lab3` и `university_lab3`. Загрузка повторяема: фиксированные `ObjectId` и `replaceOne` с `upsert` не создают дубликаты. Скрипты не удаляют базы и отказываются смешивать учебные данные с посторонними документами в целевых коллекциях.

Для запуска отдельных частей:

```bash
docker compose -f lab3/docker-compose.yml exec -T mongodb mongosh --quiet --file lab3/library_seed.js
docker compose -f lab3/docker-compose.yml exec -T mongodb mongosh --quiet --file lab3/library_queries.js
docker compose -f lab3/docker-compose.yml exec -T mongodb mongosh --quiet --file lab3/university_seed.js
docker compose -f lab3/docker-compose.yml exec -T mongodb mongosh --quiet --file lab3/university_queries.js
```

Остановка сервера с сохранением данных:

```bash
docker compose -f lab3/docker-compose.yml down
```

## Windows без прав администратора: занятие 1, задания 1–2

1. Скачайте ZIP-версии MongoDB Community Server, `mongosh` и MongoDB Compass, распакуйте их в каталоги своего пользователя. Создайте каталог данных. Это не требует записи в защищённые системные каталоги или установки службы.
2. Запустите сервер в отдельном окне PowerShell, подставив путь к распакованному `mongod.exe`:

   ```powershell
   New-Item -ItemType Directory -Force "$env:USERPROFILE\mongodb-data"
   & "$env:USERPROFILE\mongodb\bin\mongod.exe" --dbpath "$env:USERPROFILE\mongodb-data" --bind_ip 127.0.0.1 --port 27017
   ```

3. Оставьте это окно открытым. Запустите Compass, выберите **New Connection**, URI `mongodb://127.0.0.1:27017/`, имя `My_server`, затем **Save & Connect**. Это же подключение подходит к серверу Docker.
4. В другом окне перейдите в корень клонированного репозитория и запустите:

   ```powershell
   mongosh "mongodb://127.0.0.1:27017/" --file lab3/run.js
   ```

   Если `mongosh` не добавлен в PATH, используйте полный путь к `mongosh.exe`.

5. Обновите список баз в Compass: появятся `library_lab3` и `university_lab3`. Документы и результаты можно просматривать в Compass. В его встроенной оболочке скрипты также запускаются через `load(...)`, если рабочий каталог и пути настроены на репозиторий.

GUI-установка и подключение Compass описаны для выполнения на компьютере пользователя; автоматические проверки проведены на сервере MongoDB в отдельном контейнере.

## Библиотека и исправления примеров

База содержит **20 авторов, 41 книгу, 8 читателей и 65 выдач**. Коллекции: `authors`, `books`, `readers`, `borrowings`. Ссылки создаются программно, включая обоих Стругацких и пару Ильф–Петров; вручную заменять `ObjectId("…")` не требуется.

Примеры в документе используют разные имена и типы одних и тех же полей. В решении приняты имена из примеров с данными:

- `totalCopies`, `availableCopies`, `birth_year`, `book_ids`, `borrowings`;
- `author_ids`, `book_ids`, `genres`, `language`, `country` всегда массивы;
- даты выдачи, возврата, рождения и регистрации — BSON Date, а числовые поля — BSON Int32;
- `returned` — boolean; `readers.borrowedBooks` содержит вложенные сведения об активных выдачах.

Два возврата книги «Ревизор» у Соколова и Данилова исправлены с `2024-03-30` на `2025-03-30`: исходная дата предшествовала выдаче `2025-02-23` и давала отрицательный срок чтения. Исправлены биографические опечатки: Набоков — Владимир Владимирович; Фолкнер родился в 1897, Уэллс — в 1866 году. Пример первой выдачи Иванову загружается один раз: он уже присутствует в таблице из 65 строк.

ISBN сохранены как учебные строки из документа: там есть некорректные и повторяющиеся значения, поэтому уникальность и контрольная сумма ISBN не навязываются. Значения `availableCopies` также сохранены из исходного документа как отдельный снимок фонда. Их сумма не обязана равняться `totalCopies` минус активные записи приведённой истории выдач. Запрос 14 считает именно `availableCopies`, а запрос 21 — выдачи с `returned: false`. Даты регистрации и остальные исторические значения не корректируются.

### Неоднозначные формулировки запросов

- В запросе 6 XIX век — **1801–1900** включительно. Пушкин (1799) не входит.
- В запросе 16 документ не определяет, какие издательства региональные. По умолчанию их список пуст: перечислены крупные федеральные издательства. При иной классификации передайте список названий в `LAB3_REGIONAL_PUBLISHERS`, например:

  ```bash
  docker compose -f lab3/docker-compose.yml exec -T -e 'LAB3_REGIONAL_PUBLISHERS=["Название издательства"]' mongodb mongosh --quiet --file lab3/library_queries.js
  ```

- «На руках» всегда означает `returned: false`, независимо от того, истёк ли срок возврата. «Прочитал» в запросе 52 — завершённая выдача `returned: true`.
- В запросах 20 и 40 число выданных экземпляров — число операций выдачи: повторная выдача того же издания учитывается снова. Физические экземпляры по отдельным инвентарным номерам в документе не представлены.
- В запросах 37–38 все авторы сохраняются, включая авторов без книг; соавтору засчитываются все экземпляры и издания его книг.
- В запросе 49 хотя бы одна книга автора должна одновременно иметь несколько жанров; просто наличие двух разных одножанровых книг не подходит.
- В запросе 50 среднее активных выдач считается **по всем зарегистрированным читателям**, включая читателей с нулём выдач.
- Запросы 17, 31, 44, 48 и 52 возвращают всех участников при совпадении результата. Запрос 56 требует единственного читателя со строго большим числом выдач, чем у любого другого; при ничьей результат пуст.
- В запросе 55 «первый день» — день первой выдачи, включая все книги, взятые в этот день. Читатели без истории выдач не попадают в этот запрос. Календарные дни и годы считаются в UTC.

## Собственная база «Учебный центр»

Учёт кафедр, преподавателей, студентов, курсов, записей на обучение, аудиторий, занятий и платежей. База использует ссылки ObjectId, массивы компетенций и интересов, вложенный адрес кафедры, списки посещавших занятие студентов, BSON Date и Int32. Учебные персональные данные синтетические; почтовые адреса используют домен `example.test`.

| Коллекция | Документов | Основные связи и поля |
|---|---:|---|
| `departments` | 10 | Код, название, вложенный адрес |
| `teachers` | 10 | Кафедра, компетенции, ставка |
| `students` | 12 | Билет, имя, дата рождения, интересы |
| `courses` | 12 | Кафедра, массив преподавателей, стоимость, формат |
| `enrollments` | 24 | Студент, курс, статус, оценка |
| `classrooms` | 10 | Корпус, вместимость, оборудование |
| `lessons` | 24 | Курс, преподаватель, аудитория, даты, посещаемость |
| `payments` | 20 | Запись на курс, студент, сумма, статус |

Есть уникальные индексы на кодах, читательских/студенческих билетах и паре студент–курс, а также индексы для связей и поиска по датам. Запросы охватывают фильтрацию, соединения, группировки, средние, максимумы с совпадениями, отсутствующие связи, задолженность, расписание и посещаемость. Ожидающие платежи не входят в выручку; долг — цена курса минус сумма успешных платежей.

## Проверки

```bash
docker compose -f lab3/docker-compose.yml exec -T mongodb mongosh --quiet --file lab3/tests.js
```

Проверки работают в отдельных базах `library_lab3_tests` и `university_lab3_tests`. Все **57 + 20** результатов сравниваются с независимыми расчётами по загруженным документам. Дополнительно проверяются ссылки, объёмы коллекций, контрольные суммы, сортировка, повторная загрузка, ничьи, автор без книг, ровно пять/шесть книг на руках и несколько выдач в разные часы первого дня. Временные документы удаляются в `finally`.

Проверено на **MongoDB 8.0.34: 145 PASS**. Ошибка проверки выбрасывает исключение и завершает `mongosh` с ненулевым кодом. Названия баз можно изменить переменными `LAB3_LIBRARY_DB`, `LAB3_UNIVERSITY_DB`; для тестовых баз — `LAB3_TEST_LIBRARY_DB`, `LAB3_TEST_UNIVERSITY_DB`.
